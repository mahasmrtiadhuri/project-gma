# Contributing

Keep changes focused on a reproducible problem or a specific improvement. Read the README for setup and project scope before modifying the application.

## Before submitting

- Describe the trigger and expected behavior.
- Run the relevant available checks and report the actual result.
- Add regression coverage when changing business rules or error handling.
- Document configuration changes and known limitations.
- Keep credentials, private data, and local environment files out of commits.

For interface changes, include captures from the running application when possible. Do not claim a check passed unless it was run. A pull request should explain both the change and how a reviewer can verify it.
